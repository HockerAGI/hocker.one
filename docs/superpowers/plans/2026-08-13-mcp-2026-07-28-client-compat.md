# MCP 2026-07-28 Client Compatibility Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Upgrade Hocker One's existing MCP client to prefer the MCP `2026-07-28` stateless protocol while preserving compatibility with legacy initialize-capable MCP servers.

**Architecture:** Keep Hocker One's existing MCP Registry, MCP Policy and Owner Gate as the only governed cloud-action path. Modernize only the transport/client negotiation layer: probe `server/discover` with the modern per-request metadata and routing headers, then fall back to the existing `initialize` flow when a server does not support the modern revision. No provider is granted new permissions and no new external service is enabled by this change.

**Tech Stack:** Node 22, TypeScript 5.9, Node test runner, MCP JSON-RPC over HTTP.

## Global Constraints

- No direct writes to `main`.
- No secret, token, credential or environment value changes.
- No new provider activation.
- Owner Gate and existing provider/tool policy remain authoritative.
- Modern protocol revision: `2026-07-28`.
- Legacy compatibility remains available for existing initialize-capable servers.
- No production deployment until exact-head CI and Preview are green.
